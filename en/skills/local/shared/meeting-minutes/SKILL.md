# Meeting minutes and summaries

Helps the reader know: what was decided, who does what, what is still open. Use the organisation's
minutes template if there is one; the frame below is only a suggestion.

## How to work

Fill in meeting details (time, place, attendees) only when the source has them. Group content by
topic rather than in the order things were said. For a long record, summarise the main points; do not
copy every turn of speech.

Separate four kinds of information, because this is where minutes often get mixed up:

| Kind | How to write it |
|---|---|
| Discussion | Short, give the main opinions; name the person when the source has it and it matters. |
| Decisions | Record only what was clearly agreed; do not turn opinions into decisions. |
| Action items | Table: Task, Owner, Deadline. A cell not mentioned reads "not stated". |
| Open points | Issues still open, things to confirm, or who must answer. |

Keep figures, proper names and document codes as they are. If you are unsure of the speaker or a name
(especially in a speech-to-text transcript), mark it `[?]` rather than guess. If the source
contradicts itself, give both versions and do not choose one yourself.

## When delivering

The conversation or a short file is usually enough. Export to Word only when asked. Put "Decisions"
and "Action items" first if the reader mainly needs to act.

Ask again only when the owner or deadline of an important task is truly missing from the source and
cannot stay as "not stated". Put it in a single question. Do not set reminders, draft emails or make
a follow-up plan unless asked.
