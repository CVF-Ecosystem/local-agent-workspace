# Procedure documents and department organisation charts

A long internal document (usually 3 to 10 pages), issued with a code and sign-off like a quality-management document: it describes the structure, staff, business procedures and related forms of one
unit. Different from an official letter (no "To:", no "Basis") and from a form filled once. Step tables, RACI and flow diagrams: `process-mapping`. Short template skeleton: `procedure-template.md`.
Word technique: `word-technical-notes.md`.

## Suggested structure

1. Issuing organisation and drafting unit; date aligned right.
2. Document title.
3. **Document-code table**: Document code, Issue number, Effective date, Page count. Set the code by the unit's convention (for example `QT-[UNIT ABBREVIATION]-01`).
4. **Three-level sign-off table**: Drafted by, Checked by, Approved by. Assign roles by the unit's issuing authority: the approver is set by the regulation, the checker is usually the
   unit's direct head, the drafter is a deputy or the staff member in charge of the work. **If the source does not tell who holds a post** (the post is vacant, or there is only a signature without a name),
   leave the name cell empty and give only the title; never invent or guess a name.
5. **Revision history**: a short italic paragraph giving the issue number and what changed; say clearly whether this is a format standardisation or a business change.
6. **Table of contents** listing the Roman-numeral sections, then a page break.
7. **Business content**: when only the format is being standardised, keep 100% of the original content (staff, organisation chart, job descriptions by title, flow charts, tables, figures) and change only the presentation.
   A procedure written as running prose ("Step 1: ... then Step 2: ...") becomes a five-column table: Step, Work content, Performed by, Action or voucher, Deadline (bold shaded header, repeated
   when the page breaks, no row split across two pages). Content already in another suitable table (such as No., Job title, Main duties) stays as it is. Deadlines only where the source has them.
8. **Footer**: document code, issue number, automatic page number. The page count in the code table matches the real page count.
9. **Drop the closing "Recipients / Title / Name" signature block** of the original if the sign-off table at the top now serves that role, so it is not repeated in two places.

## How to work

- Extract the organisation-chart and flow-chart images embedded in the source file, look at each image to match it to the right section, then reuse it; do not redraw.
- Read the whole source text before rebuilding so no business content is missed or changed.
- Bringing many documents of many units to one standard: compare with one reference document of the unit first, look at each file as an image, then apply across the batch.
- Any name, limit, time cut-off and issue date that has no appointment or approval yet is written "provisional" or left blank.
