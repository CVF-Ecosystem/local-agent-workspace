# Comparing two versions of a document

The aim is to show the reader **what really changed**, not to list every character difference.

## How to work

Identify the old and the new version. If it is unclear which is newer, ask once and carry on. Read
both fully for the part being compared; if the question is only about one section, compare only that section.

Build the table:

| Section / clause | Old | New | Type | Impact |
|---|---|---|---|---|

- **Type:** added, removed, changed content, moved. A move that does not change the meaning gets one line.
- **Impact:** write it only when the text gives a basis (who must act differently, a new deadline, a
  new form). If unclear, write "needs confirmation"; do not infer consequences.
- Put changes to **figures, deadlines, roles, authority and conditions** first.
- Ignore differences of formatting, spelling or renumbering when the meaning is unchanged. If there
  are many, say so in one general sentence instead of listing them.
- Quote short passages verbatim when paraphrasing could shift the meaning.

If a file cannot be read completely (tables, images, scanned text), say which part could not be compared.

## When delivering

Open with a 2 to 4 sentence summary: how many significant changes and the most important group. Create
a Word/Excel file only if the user asks; by default the table stays in the conversation. Before
delivering, check the figures, dates and names in the table against both versions once.

Do not offer an opinion on which version to choose, and do not draft a merged version or a cover
letter unless asked. When the table answers the question, stop.
