# skills/local/project/

Guidance or template usage specific to the project/unit, if really useful.

Examples: how to produce a particular report or use an internal form. Authoritative business rules
stay in the source/reference; a skill can point to that source instead of copying it as a second
policy. Do not put session history into a skill.

Update `.agent/SKILL_INDEX.md` when adding or substantially changing one (paths from the project
root). There is no need to create a project skill if a native or shared skill already meets the need.
